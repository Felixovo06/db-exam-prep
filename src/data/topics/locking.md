### 一、并发会出什么问题？（三类不一致）

设数据项 $A$ 初值为 100，下面用时间线演示。

**① 丢失修改**：两个事务读同一数据，各自修改，后写的覆盖了先写的。

| 时间 | $T_1$ | $T_2$ |
|---|---|---|
| $t_1$ | 读 $A=100$ | |
| $t_2$ | | 读 $A=100$ |
| $t_3$ | $A=A-10$，写回 90 | |
| $t_4$ | | $A=A-20$，写回 80 |

结果 $A=80$，$T_1$ 的修改丢失了（正确应为 70）。

**② 读“脏”数据**：$T_1$ 修改后尚未提交，$T_2$ 读到这个值，随后 $T_1$ 回滚。

| 时间 | $T_1$ | $T_2$ |
|---|---|---|
| $t_1$ | 写 $A=90$ | |
| $t_2$ | | 读 $A=90$ |
| $t_3$ | ROLLBACK（$A$ 恢复 100） | |

$T_2$ 读到的 90 是无效的“脏”数据。

**③ 不可重复读**：$T_1$ 两次读同一数据，中间 $T_2$ 修改了它。

| 时间 | $T_1$ | $T_2$ |
|---|---|---|
| $t_1$ | 读 $A=100$ | |
| $t_2$ | | 写 $A=90$ 并提交 |
| $t_3$ | 再读 $A=90$ | |

$T_1$ 前后两次读取结果不一致。（若 $T_2$ 是插入/删除了满足条件的记录，则称为**幻影现象**。）

### 二、锁的类型与相容矩阵

| | 已持有 S 锁 | 已持有 X 锁 |
|---|---|---|
| **请求 S 锁** | ✔ 相容（可同时读） | ✘ 等待 |
| **请求 X 锁** | ✘ 等待 | ✘ 等待 |

- **S 锁（共享锁）**：只能读，不能写，多个事务可同时持有；
- **X 锁（排他锁）**：可读可写，持有期间别的事务**不能再加任何锁**。

### 三、三级封锁协议（必背）

| 级别 | 规则 | 解决的问题 |
|---|---|---|
| **一级** | 修改数据前加 **X 锁**，**事务结束**才释放（读不加锁） | 防止**丢失修改** |
| **二级** | 一级 + 读数据前加 **S 锁**，**读完立即释放** | + 防止**读“脏”数据** |
| **三级** | 一级 + 读数据前加 **S 锁**，**事务结束**才释放 | + 防止**不可重复读** |

**为什么有效（以演示③为例）**：三级协议下 $T_1$ 读 $A$ 时加 S 锁并保持到结束，$T_2$ 想修改 $A$ 需要 X 锁，与 S 锁冲突，只能等待，所以 $T_1$ 两次读到的值相同。
**二级为什么挡不住它**：二级读完就释放 S 锁，$T_2$ 就能在两次读之间插进来修改。

### 四、两段锁协议（2PL）

- **规则**：每个事务分两个阶段——**扩展（加锁）阶段**只加锁不解锁；**收缩（解锁）阶段**只解锁不加锁。**一旦开始释放锁，就不能再申请新锁。**
- **结论**：遵守 2PL 的调度**一定是可串行化的**；但可串行化的调度**不一定**遵守 2PL；2PL **不能避免死锁**。

**判断一个事务是否遵守 2PL（例题）**：

- 事务 $T_a$：`Lock A → Lock B → Unlock A → Lock C → Unlock B → Unlock C`
  - 在 `Unlock A` 之后又 `Lock C` ⇒ **不遵守** 2PL。
- 事务 $T_b$：`Lock A → Lock B → Lock C → Unlock A → Unlock B → Unlock C`
  - 所有加锁都在第一个解锁之前 ⇒ **遵守** 2PL。

### 五、可串行化判定（冲突可串行化，会画“前驱图”）

**冲突操作**：不同事务对**同一数据项**的操作，且至少一个是**写**。
**判定步骤**：
1. 按调度顺序，找出所有冲突操作对；若 $T_i$ 的操作排在 $T_j$ 前面，画边 $T_i\to T_j$；
2. 看前驱图**有没有环**：**无环 ⇒ 冲突可串行化**，环外按拓扑顺序即为等价的串行顺序；**有环 ⇒ 不可串行化**。

**例**：调度 $S$：`R1(A) W1(A) R2(A) W2(A) R1(B) W1(B)`（下标是事务号）。
- $A$ 上：$W_1(A)$ 在 $R_2(A)$、$W_2(A)$ 前 ⇒ 边 $T_1\to T_2$；
- $B$ 上只有 $T_1$ 操作，无冲突；
- 前驱图中只有一条边 $T_1\to T_2$，**无环** ⇒ **可串行化**，等价于先执行 $T_1$、再执行 $T_2$。

**例（不可串行化）**：`R1(A) W2(A) W1(A)`：$R_1(A)$ 在 $W_2(A)$ 前 ⇒ $T_1\to T_2$；$W_2(A)$ 在 $W_1(A)$ 前 ⇒ $T_2\to T_1$；有环 ⇒ 不可串行化（这正是“丢失修改”）。

### 六、死锁

- **产生**：两个事务互相等待对方持有的锁。例如 $T_1$ 持有 $A$ 的 X 锁等 $B$，$T_2$ 持有 $B$ 的 X 锁等 $A$。
- **预防**：一次封锁法（一次性申请全部锁）、顺序封锁法（统一加锁顺序）；
- **诊断**：超时法、**等待图法**（图中有环即死锁）；
- **解除**：选择代价最小的事务**撤销**，释放其锁。

### 七、易错点

1. 一级协议**只对写加锁，读不加锁**；
2. 二级协议读完就释放 S 锁，所以不能防不可重复读；
3. 遵守 2PL ≠ 不会死锁；
4. “可串行化”是并发调度**正确性的唯一准则**；
5. 区分 **“幻影”** 与 **“不可重复读”**：前者是记录集合变了（多了/少了行），后者是同一行的值变了。
