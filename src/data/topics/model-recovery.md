### 一、数据模型的三要素

| 要素 | 含义 | 例子 |
|---|---|---|
| **数据结构** | 静态特征：数据的类型、内容、性质及相互联系 | 关系模型中的“关系（二维表）” |
| **数据操作** | 动态特征：对数据允许执行的操作及规则 | 查询、插入、删除、更新 |
| **数据的完整性约束条件** | 一组完整性规则，保证数据正确、有效、相容 | 实体完整性、参照完整性、用户定义完整性 |

**三类完整性**：
- **实体完整性**：主码值唯一且**不能为空**；
- **参照完整性**：外码的值要么为空，要么是被参照关系中某个主码值；
- **用户定义完整性**：由应用语义决定，如“成绩在 0~100”“性别只能是男或女”。

### 二、事务与 ACID

**事务**：用户定义的一个**不可分割**的操作序列，是恢复和并发控制的基本单位。

| 特性 | 含义 | 由谁保证 |
|---|---|---|
| **A 原子性** | 要么全做，要么全不做 | 恢复机制（UNDO） |
| **C 一致性** | 事务把数据库从一个一致状态变到另一个一致状态 | 由用户保证 + DBMS 配合 |
| **I 隔离性** | 并发执行的事务互不干扰 | 并发控制（封锁） |
| **D 持久性** | 事务一旦提交，修改永久保存，即使故障也不丢 | 恢复机制（REDO、日志） |

**例（转账）**：从账户 $A$ 向 $B$ 转 100 元。操作序列：$A-100$，$B+100$。
- 原子性：两步要么都完成，要么都不做，不能只扣了 $A$ 没加 $B$；
- 一致性：转账前后 $A+B$ 的总额不变；
- 隔离性：别的事务不能看到“只扣了 $A$”的中间状态；
- 持久性：提交后，即使马上断电，转账结果也不会丢。

**事务控制语句**：
```sql
BEGIN TRANSACTION;      -- 开始（有的系统隐式开始）
...                     -- 一组操作
COMMIT;                 -- 提交：事务成功结束，修改永久生效
-- 或
ROLLBACK;               -- 回滚：事务失败，撤销所有已做的修改
```

### 三、故障类型与恢复策略

| 故障 | 例子 | 影响 | 恢复策略 |
|---|---|---|---|
| **事务故障** | 逻辑错误、死锁被撤销 | 个别事务中止 | **UNDO**：反向扫描日志，撤销该事务的修改 |
| **系统故障** | 断电、操作系统崩溃 | **内存**数据丢失，外存数据完好 | 重启后：对**未完成**事务 **UNDO**，对**已提交但未写回**的事务 **REDO** |
| **介质故障** | 磁盘损坏 | **外存**数据丢失 | 装入最近的**后备副本（转储）**，再用日志 **REDO** 已提交事务 |
| **计算机病毒** | 恶意破坏 | 数据被破坏 | 类似介质故障，利用后备副本和日志恢复 |

### 四、日志与检查点

**日志文件**：按时间顺序记录所有更新操作，记录内容包括：事务标识、操作类型、数据对象、**更新前的旧值**（用于 UNDO）、**更新后的新值**（用于 REDO）。

**登记日志的两条原则**：
1. 日志记录的顺序必须与事务执行的顺序一致；
2. **先写日志，后写数据库**（先写日志文件 WAL）。

**检查点**：为了避免重启恢复时扫描整个日志，系统定期设置检查点，把内存中的更新写回磁盘并在日志中记一个检查点记录。检查点**之前**已提交的事务，其修改已落盘，**不需要 REDO**。

#### 例：根据日志判断恢复动作

日志序列（时间由上到下）：

| 序号 | 日志记录 |
|---|---|
| 1 | $\langle T_1\ \text{START}\rangle$ |
| 2 | $\langle T_1,\ A,\ 10,\ 20\rangle$ |
| 3 | $\langle T_1\ \text{COMMIT}\rangle$ |
| 4 | **检查点** |
| 5 | $\langle T_2\ \text{START}\rangle$ |
| 6 | $\langle T_2,\ B,\ 5,\ 6\rangle$ |
| 7 | $\langle T_2\ \text{COMMIT}\rangle$ |
| 8 | $\langle T_3\ \text{START}\rangle$ |
| 9 | $\langle T_3,\ C,\ 1,\ 2\rangle$ |
| — | **系统故障（崩溃）** |

**分析**：
- $T_1$：在检查点**之前**已提交，修改已落盘 ⇒ **无需任何处理**；
- $T_2$：检查点**之后**开始并已提交，但修改可能还没写盘 ⇒ **REDO**（把 $B$ 设成新值 6）；
- $T_3$：崩溃时**尚未提交** ⇒ **UNDO**（把 $C$ 恢复成旧值 1）。

### 五、数据转储

| 分类方式 | 类型 | 说明 |
|---|---|---|
| 按状态 | **静态转储** | 转储期间不允许对数据库做任何存取、修改 |
| | **动态转储** | 转储期间允许存取、修改，需配合日志文件保证一致 |
| 按方式 | **海量转储** | 每次转储全部数据 |
| | **增量转储** | 只转储上次转储以来更新过的数据 |

### 六、选择/填空高频点

1. 数据模型三要素：**数据结构、数据操作、完整性约束**（不是“数据存储”）；
2. ACID 的四个字母对应：原子性、一致性、隔离性、持久性；
3. 事务以 **COMMIT** 或 **ROLLBACK** 结束；
4. 事务故障靠 UNDO，系统故障靠 UNDO+REDO，介质故障靠“转储+日志”；
5. **先写日志，后写数据库**。
