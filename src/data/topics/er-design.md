### 一、E-R 图的四个要素

| 图形 | 含义 | 画法要点 |
|---|---|---|
| 矩形 | **实体**（如学生、课程） | 框内写实体名 |
| 椭圆 | **属性** | 用线连到实体/联系；**主码属性加下划线** |
| 菱形 | **联系**（如选修、借阅） | 连接相关实体，**连线上标 1、N、M** |
| 连线上的 1/N/M | **联系类型** | 1:1、1:N、M:N |

**联系自己的属性**（如选修的“成绩”、借阅的“借出日期”）要画在**菱形**上，不要画到某个实体里。

### 二、从题干读出联系类型

| 题干说法 | 联系类型 |
|---|---|
| “一个学生只能属于一个单位，一个单位有多个学生” | 单位 **1 : N** 学生 |
| “一个学生可选多门课，一门课可被多个学生选” | 学生 **M : N** 课程 |
| “每个经纪人负责一个歌手，每个歌手只有一个经纪人” | **1 : 1** |

读法：**分别从两个方向问“一个 A 对应几个 B”**，两个答案都是“多个”就是 M:N，一个“一个”一个“多个”是 1:N，两个都是“一个”是 1:1。

### 三、E-R 图转关系模式（4 条规则）

1. **每个实体** → 一个关系模式，属性是实体的全部属性，实体的码是主码。
2. **1:N 联系** → **不单独建表**。把 **1 端的主码**（以及联系的属性）放进 **N 端**的关系模式，作为 N 端的**外码**。
3. **M:N 联系** → **必须单独建一个关系模式**，属性 = 双方实体的主码 + 联系自身的属性，主码是双方主码的组合，且各自又是指向对应实体的外码。
4. **1:1 联系** → 可以把任意一端的主码（及联系属性）并入另一端作外码，也可以单独建表（二选一，不要两边都放）。

> 记忆口诀：**一对多，主码放“多”端；多对多，单独建新表；一对一，合并任意端。**

### 四、完整例题

**题**：某图书馆有读者（借书证号、姓名、单位）、图书（书号、书名、出版社）、职工（工号、姓名）。一位读者可借多本书，一本书可被多位读者借阅，借阅需记录借出日期和归还日期；一位职工可管理多本书，一本书只由一位职工管理。

**第 1 步：识别实体与联系**
- 实体：读者、图书、职工；
- 联系：**借阅**（读者 M : N 图书，属性：借出日期、归还日期）；**管理**（职工 1 : N 图书）。

**第 2 步：画图（文字描述）**
- 矩形“读者”—[菱形“借阅”(借出日期、归还日期)]—矩形“图书”，两侧标 M、N；
- 矩形“职工”—[菱形“管理”]—矩形“图书”，职工一侧标 1，图书一侧标 N；
- 各实体的属性用椭圆连接，主码（借书证号、书号、工号）下划线。

**第 3 步：转换为关系模式（<u>下划线</u>为主码，外码另注）**
1. 读者（<u>借书证号</u>，姓名，单位）
2. 职工（<u>工号</u>，姓名）
3. 图书（<u>书号</u>，书名，出版社，管理工号）　外码：管理工号 → 职工(工号)　*（1:N 的“管理”并入 N 端）*
4. 借阅（<u>借书证号，书号</u>，借出日期，归还日期）　外码：借书证号 → 读者，书号 → 图书　*（M:N 单独建表）*

**检查清单**：4 个关系模式 = 3 个实体 + 1 个 M:N 联系；1:N 联系没有单独建表；每个表主码标了，外码写明了参照关系。

### 五、E-R 图的集成与冲突（选择/填空会考）

全局 E-R 图由多个**局部 E-R 图**合并而成，合并时要消除三类冲突：

| 冲突 | 含义 | 例子 |
|---|---|---|
| **属性冲突** | 同一属性的域或取值单位不一致 | 学号有的用字符型、有的用整型；体重有的用公斤、有的用斤 |
| **命名冲突** | **同名异义**或**异名同义** | “单位”在一处指院系、在另一处指企业；“教师”与“老师” |
| **结构冲突** | 同一对象在不同局部图中抽象不同（有的作实体，有的作属性），或同一实体在不同图中属性组成不同 | “职称”在一个图里是属性，在另一个图里是实体 |

合并后还要**消除冗余**：冗余数据（可由基本数据导出的属性）和冗余联系（可由其他联系推导的联系）。

### 六、考场易丢分点

- 题目要求“**标明主码和外码**”，漏标外码扣 2~3 分；
- M:N 联系漏建独立关系模式；
- 联系的属性（日期、数量、成绩）漏写；
- 1:N 联系错误地单独建表并以双方主码为联合主码，会让“1”端实体重复出现；
- 题干没有的联系不要凭空添加，题干没有的属性不要乱加（要加代理主码时注明）。
